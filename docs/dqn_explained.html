DQN, explained from PPO

You know PPO end to end: an actor and a critic, rollouts with the frozen π_old, GAE, a batch used for several epochs in minibatches, then thrown away. DQN keeps the critic's core idea (bootstrapped value targets), drops the actor entirely, and adds two new parts that make it work: a replay buffer and a target network. Every section below starts from the PPO piece you already know.

1

One network that scores every action

PPO has two networks: the actor says what to do (probabilities π(a|s)), the critic says how good this state is (V(s)). DQN has one network with one output per action: Q(s, a), the return you expect if you take action a now and act well afterwards. There is no actor: the policy is simply "take the action with the largest Q".

The bridge: PPO's advantage is Q − V

In PPO you never computed Q, but you used it all the time: the advantage A(s, a) = Q(s, a) − V(s) says how much better action a is than the policy's average. PPO estimates A from what actually happened in the rollout (GAE). DQN learns Q for every action directly. Press the buttons to move between the two views of the same LunarLander state.

The max makes Q-learning learn Q*, the value of the best policy, whatever policy collected the step. That is what later allows a replay buffer full of old, random-ish experience.

From a table to a network: the DQN loss

LunarLander has continuous states, so a table is impossible: DQN replaces it with a network Qθ. The update becomes a regression, just like PPO's critic: compute a target y, then take a gradient step on (Qθ(s, a) − y)². Only the output of the action that was actually taken has an error; the other three outputs get no gradient from this transition. Change the inputs and watch the target and the error.

4

Exploration: sampling π vs ε-greedy

PPO explores because its policy is stochastic: it samples from π, and the entropy (temperature) controls how random that is. DQN's greedy policy is deterministic, so exploration is added from outside: with probability ε take a uniformly random action, otherwise the argmax. ε starts at 1 (fully random) and decays on a fixed schedule.

Who decides how randomPPO: the learning itself (entropy falls as π sharpens). DQN: a schedule you choose (ε from 1.0 to 0.05 over, say, the first 10% of training).
What is randomPPO's exploration prefers good actions (it samples in proportion to π). ε-greedy picks the worst action as often as the second best.
At test timeBoth act greedily: argmax π for PPO, argmax Q for DQN (ε = 0 or a small 0.01).
5

The replay buffer: DQN's version of "batch + epochs"

In PPO a batch is played by π_old, used for K epochs in minibatches, then thrown away: after the update it no longer comes from the current policy, and PPO's gradient needs data from (nearly) the current policy. DQN's max target does not care who collected the data, so it keeps the last N transitions (s, a, r, s′, done) in a buffer and trains on random minibatches from it, a little after every environment step. 1 · It breaks correlationConsecutive steps are almost the same state. A minibatch of them pulls every gradient step toward one small region, exactly what we saw with 64-step batches in the one-step PPO experiment (the zigzag plots). Random samples from a large buffer look like the whole state space.
2 · It reuses experiencePPO reuses a batch K times (epochs) and then forgets it. DQN reuses each transition across many updates for as long as it stays in the buffer: the replay ratio (gradient samples ÷ new transitions) plays the role of PPO's epochs.
3 · It is only allowed off-policyThe data in the buffer came from older, more random policies (look at the age). The max target learns Q* anyway. PPO cannot do this: its ratio π/π_old corrects only small differences, and the clip forbids large ones.
6

The target network: freeze what the target is made of

The target y = r + γ·max Q(s′, ·) is computed with the same kind of network that is being trained. Every gradient step changes all of Q, including Q(s′, ·), so the target moves while you chase it, and with generalisation across states the errors can feed on themselves. DQN keeps a second copy, the target network θ⁻, that is only used to compute y and is refreshed every C steps (or slowly, θ⁻ ← τθ + (1−τ)θ⁻).

online θ trained every step, picks the actions
copy θ → θ⁻ every 100 steps

Toy simulation of one Q-value. Its next-state value Q(s′) also shifts as the network learns other states (random drift). Top: the target uses the live network, so it moves every step and the prediction chases it. Bottom: the target uses the frozen copy, so for 100 steps it is a fixed regression target. Both start at the true value. The price: new information reaches the target only at the next copy, so a target network also slows learning a little; C trades stability for speed.

You have seen this idea in PPO PPO computes its advantages and critic targets once per batch with V_old, and keeps them fixed for all 10 epochs, even though the critic changes after every minibatch. That is a target network with C = one batch. DQN needs an explicit copy only because it never stops to collect a batch: it updates after every step, so "the critic before the update" has to be stored somewhere.

8

Where plain DQN goes wrong, and the fixes that became Rainbow

The 2015 DQN (replay + target network) works, but it has known weaknesses. Each fix below is one idea; Rainbow (2017) combines six of them. Our final step uses the four that matter most at LunarLander's size.

8a · Overestimation, and Double DQN

The target takes a max over noisy estimates. Even if every action is truly worth 0, the largest of four noisy guesses is usually above 0, so targets are biased upward, and the bias is copied backwards through bootstrapping. Double DQN separates choosing from scoring: the online network picks a′ = argmax Qθ(s′, ·), the target network scores it, Qθ⁻(s′, a′). Their noise is (mostly) independent, so the bias disappears. Draw samples and watch the running averages.

True value of every action: 0. "DQN target" = max of one set of noisy estimates; "Double DQN" = choose with set A, score with an independent set B.

8b · Dueling heads: V and A inside Q

The network splits after its shared layers into a value head V(s) and an advantage head A(s, a), then recombines them. This is literally PPO's critic and PPO's advantage, learned inside one network. It helps because V is learned from every transition, even in states where the action barely matters (high in the sky, every action is similar).

8c · n-step returns: DQN's version of GAE

A one-step target trusts the network after a single real reward; Monte Carlo trusts only real rewards. PPO solved this with GAE's λ, an exponentially weighted mix of all k-step lookaheads. DQN variants use one fixed n: y = rt + γrt+1 + … + γn−1rt+n−1 + γn·max Qθ⁻(st+n, ·). Rainbow uses n = 3.

Bars: how much weight each k-step lookahead gets in the target. n-step puts all of it on k = n; GAE spreads it as (1 − λ)λk−1 (mean lookahead 1/(1 − λ)). One catch for DQN: the n rewards in the buffer were earned by an older, ε-greedy policy, so n-step targets are slightly off-policy; small n keeps that harmless.

8d · Prioritized replay, and the other two Rainbow parts

Prioritized replay

Sample transitions in proportion to their last |TD error|α instead of uniformly: the surprising ones are replayed more. Because that changes the data distribution, each sample's loss is weighted by (N·P(i))−β, an importance weight, the same correction idea as PPO's ratio π/π_old.

Distributional (C51)

Learn the whole distribution of returns (51 bins) instead of only its mean Q. A richer target that often learns faster on Atari; heavier to implement. Left for later.

Noisy networks

Replace ε-greedy with learned noise in the weights, so the amount of exploration is learned per state, closer to how PPO's entropy works. Left for later.

typical usesAtari-style games, recommendation and ads, settings where interaction is expensive or logged data existsrobotics and continuous control, cheap fast simulators, fine-tuning language models

For continuous actions the off-policy idea continues in DDPG, TD3 and SAC: a Q-network (critic) plus an actor that outputs the action, because a max over infinitely many actions is not practical. SAC is a later stage of our plan.
